## 三、接口 spec 与不变量

struct pmm_manager 包含 name 字符串和六个函数指针：init、init_memmap、alloc_pages、free_pages、nr_free_pages、check。name 用于标识管理器；前五个函数由 B 实现，check 接到保留的 best_fit_check()，不另写一套弱化检查。最终注册对象的 name 为 best_fit_pmm_manager，pmm.c 只改选择它的语句。实现接口如下：

```c
static void best_fit_init(void);
static void best_fit_init_memmap(struct Page *base, size_t n);
static struct Page *best_fit_alloc_pages(size_t n);
static void best_fit_free_pages(struct Page *base, size_t n);
static size_t best_fit_nr_free_pages(void);
const struct pmm_manager best_fit_pmm_manager;
```

init 初始化空闲链表头和计数。init_memmap 登记一个合法、已标记 reserved 的页区间，清理每页状态，把区间首 Page 作为空闲块头。alloc_pages 从所有满足长度至少为 n 的块中选最小块；失败返回 NULL，不改变状态。free_pages 归还调用者合法持有的区间并合并地址相邻块。nr_free_pages 返回当前空闲页总数。

输入前提为 n>0、Page 地址和区间有效，不重叠、不重复释放；n=0 会断言，不是返回 NULL。合法调用场景下检查以下不变量：

1. 只把空闲块首 Page 的 page_link 挂入 free_list，按物理地址递增排列。
2. 块头设置 PageProperty，property 表示块长；其他页的旧 property 数值不作为有效块长。
3. 空闲区间不重叠，nr_free 等于各块长度之和；失败分配不改变这两者。
4. 当前单段初始化、合法分配/释放流程中，可相邻合并的块在释放时合并。多次 init_memmap 登记相邻区间不会主动合并，这是边界而非已经实现的功能。

没有更改 struct Page、pmm_manager 接口或链表库，也没有加入并发锁和完整分配所有权记录。现有断言能发现部分非法操作，但不能保证检测所有重复释放或越界。

## 四、First-Fit 与 Best-Fit 的实现分析

### 4.1 First-Fit 如何维护空闲块

First-Fit 的 default_init 建立空链表并清零计数，default_init_memmap 清理 Page、登记块头并按地址插入。default_alloc_pages 从头遍历，遇到第一个 property>=n 的块就选择它；大于 n 时从块首分配并将余块放回原位置。default_free_pages 按地址归还区间并检查相邻块，default_nr_free_pages 返回计数。因此，链表顺序、块分裂和相邻合并是机制；“遇到第一个可用块就停”是 First-Fit 的策略。

### 4.2 最小适配选择

本实现遍历所有空闲块。只有 p->property>=n 的块参与比较；当候选为空，或新块比候选严格更小时更新 best。相同大小不替换，所以按当前地址有序链表选最低地址者。找到恰好大小的块后仍继续遍历，遵守分工中的全扫描要求，不是复制 First-Fit 后只改名称。

```c
if (p->property >= n) {
    if (best == NULL || p->property < best->property) {
        best = p;
    }
}
```

例如，地址顺序存在长度 2 和 1 的空闲块，申请 1 页：First-Fit 选择 2 页块，Best-Fit 选择 1 页块。二者不一定谁在全部工作负载下更好；Best-Fit 尽量减小本次剩余空间，也可能留下难以利用的小碎片。

### 4.3 分配与切割

先保存 best 的前驱，再摘除 best。若 best->property>n，则余块为 best+n，余块长度为原块长减 n；设置余块的 PageProperty，插回原前驱之后。余块仍在原块所在的地址区间，链表保持有序。随后 nr_free 减 n，清除已分配块头的 PageProperty，返回 best。

n>nr_free 时直接失败；总空闲页够但没有任何单块足够大时，全扫描得到 best==NULL，同样失败。两条失败路径都不摘链、不切割、不改计数。已分配块头可能保留旧 property 数字，但标记已清除，不将其当作空闲块。

### 4.4 释放与前后合并

先逐页检查非 reserved、非空闲块头，清标志和引用计数；将 base 标记为长度 n 的空闲块，nr_free 仅加一次 n。找到地址插入点后插入，再检查后块：若 base+base->property==next，则扩大 base，清除 next 的块头标记并摘链。最后检查前块：若 prev+prev->property==base，则前块吸收 base，清除 base 的块头标记并摘链。两侧都相邻时最终只留下一个大块，合并不再增加 nr_free。

以下为算法手工推演，不是新增测试结果。以页索引表示地址，低地址在上：

```text
[10,12)  前空闲块：2 页
[12,15)  本次归还：3 页
[15,19)  后空闲块：4 页
先合并本次区间与后块 → [12,19)，7 页
再与前块合并         → [10,19)，9 页
nr_free 仅增加归还的 3 页
```

### 4.5 复杂度与改善方向

设空闲块数为 k、登记或归还页数为 n。alloc_pages 为 O(k)；free_pages 含逐页清理 O(n) 和有序插入查找 O(k)，合计 O(n+k)，两侧邻接合并本身为 O(1)。init_memmap 同样为 O(n+k)；统计为 O(1)。复用 Page 元数据，新增固定大小的 free_area 管理对象。

First-Fit 可以研究 Next-Fit 或分类空闲表来减少重复遍历，但选择策略及碎片分布会改变；应以负载测量判断。Best-Fit 可以用按大小组织的树或分类索引查找候选，同时保留地址索引用于合并；这样需要维护两套一致的索引，不能只改查找函数。多段初始化可补相邻合并；并发场景需同步；健壮性可补所有权、范围和重叠检查。这些是建议，没有在本次代码中偷偷扩展实现。

## 七、操作系统原理与实验边界

本实验把连续物理页分配策略落到 Page 描述符与空闲区链表上，展示了外部碎片、分裂、合并和总量不变量。物理页是分配单位，返回的是 Page 描述符；它并不是用户态虚拟地址。物理相邻与链表相邻要结合区间端点判断，链表相邻本身不保证内存连续。

pmm_manager 把统一接口与具体策略分开，B 更换管理器选择而不重写 page_init，体现策略与机制分离。页表负责地址翻译与权限，分配器负责可用物理页，两者相关但不能互相替代。内存压缩、页面置换、按需分页、多进程隔离、TLB 一致性和多核同步均没有由本次 Best-Fit 实现完整覆盖，不能把分配器通过测试等同于这些机制完成。
