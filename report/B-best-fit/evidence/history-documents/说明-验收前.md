## 二、功能 spec 与接口

`best_fit_init()` 初始化空闲链表和计数。`best_fit_init_memmap(base,n)` 将已标记 reserved 的合法区间登记为空闲块。`best_fit_alloc_pages(n)` 在所有空闲块中寻找大小至少为 n 的最小块，成功返回连续 n 页的首个 Page，失败返回 NULL，且不改变链表和计数。`best_fit_free_pages(base,n)` 归还合法已分配区间，按地址插入并合并相邻块。`best_fit_nr_free_pages()` 返回空闲页总数。管理器结构把这些函数及原有检查函数接入 `pmm_manager`。

输入前提是 n>0、Page 区间合法、不重叠且不重复释放。接口不负责修复非法释放；n=0 会触发断言，而不是返回 NULL。本实验依赖单 hart 的初始化流程，不支持无保护的并发调用。

## 三、数据结构与不变量

沿用现有 `struct Page`、`free_area_t` 和双向循环链表，不改结构或宏。空闲块只把首个 Page 挂入 `free_list`；首个 Page 的 `property` 表示块长，`PageProperty` 标记该字段当前有效。非块头或已分配页即使保留旧 property 数值，也不能把它当作空闲块长度。

链表按物理地址递增，空闲区间互不重叠，`nr_free` 等于所有空闲块长度之和。在本实验单次初始化及合法分配/释放流程下，释放后相邻块合并，避免人为保留可合并碎片。多次登记相邻区间时，当前 init_memmap 不主动合并，这是扩展场景的边界。

## 四、算法实现

### 1. 全扫描选择

遍历链表全部节点。只有 `p->property >= n` 的块可参与选择；当候选为空或新块更小时更新候选。相同大小保留先遇到的块，即最低地址块。即使找到恰好大小的块，当前实现也继续扫描，符合本次分工的全扫描要求。

First-Fit 选择地址序中第一个够大的块；Best-Fit 选择全部候选中最小的块。例如按地址存在 2 页块与 1 页块，申请 1 页时 First-Fit 会用前者，Best-Fit 用后者。这正是原有 best_fit_check 中的关键策略区分断言。

### 2. 分配和切割

先保存候选块的前驱，再摘下候选。若候选大于 n，剩余块起点为 best+n，长度为原长度减 n，并插回原位置。余块仍位于原前驱和原后继之间，地址顺序不变。最后减少 nr_free 并清除已分配首个 Page 的 PageProperty。若全部空闲页总数不足，或碎片总数够但没有单块足够大，返回 NULL 且不改状态。

### 3. 释放和双向合并

归还区间清标志和引用计数，把 base 作为块头，nr_free 只加一次 n。按地址找到插入位置后，先判断 base+property 是否等于后块首地址；相邻则加长度、清掉后块头标记并摘链。再判断前块末端是否等于 base；相邻则让前块吸收 base、清掉 base 块头标记并摘链。前后都相邻时得到一个大块，合并过程不重复增加空闲页计数。

### 4. 复杂度

设空闲块数为 k、归还页数为 n：分配扫描 O(k)；释放要先逐页清理 O(n)，再查找插入位置 O(k)，合计 O(n+k)，邻接合并自身为 O(1)。init_memmap 同样包含逐页初始化和有序插入。额外管理状态为一个空闲管理区对象，复用已有 Page 元数据，不增加按页的额外结构。

## 八、改进空间与操作系统原理

First-Fit 可用分级空闲链表或更高效的空闲区间索引降低遍历成本，也可研究 Next-Fit 改善重复从头扫描；这些改变会影响选择策略和碎片分布，需要另测。当前 Best-Fit 可用按大小索引加地址索引减少搜索成本；若扩展到多核，应增加同步；若要求健壮性，可增加所有权、重复释放和重叠检查，并在多段 init_memmap 时合并相邻区间。这些是改进建议，本次未实现。

Best-Fit 不保证对所有工作负载都比 First-Fit 少碎片，它可能产生很小的剩余块。必须测量分配延迟、可满足的大块请求比例和碎片分布，而非仅凭名称判断优劣。

本实验对应物理连续页分配、外部碎片、块分裂与合并、元数据不变量及策略与机制分离。它不等于虚拟内存换页、进程页表权限管理或通用小对象分配器；Buddy 与 SLUB 不在本人的本次实现范围。
