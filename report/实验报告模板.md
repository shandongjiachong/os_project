## 三、实验整体逻辑分析

### 3.1 本章节的逻辑主线

本实验把已有的物理页管理和 Trap 恢复机制接入线程管理。先维护虚拟地址映射，
再用 PCB、独立内核栈和初始现场描述线程，最后由调度器选择线程并恢复其执行现场。
本阶段的内核线程共享内核地址空间，地址空间框架采用预映射方式。

### 3.2 功能的逐步实现

1. 接入 Lab2 的物理页管理和 Lab3 的 Trap 保存恢复代码，为页表页和线程内核栈提供资源。
2. 实现 `page_insert()`、`page_remove()`，供启动自检和后续内存访问使用。
3. 用 `alloc_proc()` 初始化 PCB，用 `proc_init()` 将当前执行流登记为 idleproc，创建 initproc。
4. `kernel_thread()` 构造入口和参数，`do_fork()` 组织资源，`copy_thread()` 准备首次运行现场。
5. `cpu_idle()` 响应调度请求，`schedule()` 选择线程，`proc_run()` 更新线程和页表，
   `switch_to()` 保存、恢复上下文。新线程经过 Trap 返回链执行指定函数。

```text
kern_init → pmm_init → pic_init / idt_init → vmm_init → proc_init
  → cpu_idle → schedule → proc_run → switch_to
  → forkret → forkrets → __trapret → sret → kernel_thread_entry → init_main
```

### 功能模块一：虚拟内存页操作功能

**负责人：** 2413551-李睿

#### 模块功能描述

**需要实现/修改的函数：**

```c
// kern/mm/pmm.c
int  page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm);
void page_remove(pde_t *pgdir, uintptr_t la);

// 模块内部静态辅助函数（非公开接口，供上述两个函数共用）
static void page_remove_pte(pde_t *pgdir, uintptr_t la, pte_t *ptep);
```

**功能说明：**

- **在系统中的作用**：本模块位于物理内存管理与虚拟内存管理之间。`pmm.c` 中既有的
  `get_pte()` 只负责"定位/创建页表项"，本模块在它之上补齐"映射管理"能力——把某个
  线性地址所在的虚拟页建立、替换或解除到某个物理页的映射，并在整个过程中维护物理页
  的引用计数与 TLB 一致性。它是 `pmm_init()` 自检（`check_pgdir()`、
  `check_boot_pgdir()`）、`vmm.c` 的 VMA/mm 校验以及后续 `pgdir_alloc_page()`、
  `do_pgfault()`、`copy_mm()` 等功能的公共底座。
- **需要处理的主要场景**：
  1. 该虚拟页原本无有效映射 → 建立新映射，物理页引用计数加一；
  2. 该虚拟页已映射到同一个物理页 → 仅更新权限位，引用计数不变（改权限场景）；
  3. 该虚拟页已映射到另一个物理页 → 先解除旧映射（旧页减引用，归零则释放），再建立新映射；
  4. 页表页分配失败 → 返回 `-E_NO_MEM`，且不留下任何半完成状态；
  5. 解除映射时该地址本来就没有映射 → 安静返回，保证幂等。
- **与其他模块的交互关系**：
  - `get_pte()`：定位页表项并按需分配页表页（本模块不负责页表页的分配与回收）；
  - `page_ref_inc()/page_ref_dec()/free_page()`：维护物理页引用计数并在归零时回收页；
  - `pte_create()/page2ppn()/pte2page()`：页表项的构造与解析；
  - `tlb_invalidate()`：页表项被修改后失效对应虚拟页的 TLB；
  - `vmm.c`：`check_vma_struct()` 等通过本模块校验地址空间映射是否可建立/解除。

#### 实现要点

1. 抽取统一的 `static void page_remove_pte(pde_t *pgdir, uintptr_t la, pte_t *ptep)`：
   若表项有效则取物理页、减引用（归零释放）、清表项、刷 TLB，被 `page_insert()`
   的"覆盖旧映射"路径与 `page_remove()` 复用，保证两条路径语义完全一致。
2. `page_insert()` 采用"**先加引用、再判断是否同页**"的顺序：同页重映射时把刚加的
   引用减回去（净变化为 0），异页时由 `page_remove_pte()` 释放旧映射。若反过来"先减
   再加"，同一物理页的引用计数会短暂归零而被误释放，这是本模块最容易踩的坑。
3. `page_remove()` 用 `get_pte(pgdir, la, 0)`（不创建页表页）定位，返回 `NULL` 直接
   返回，从而天然满足"未映射时无副作用"和"重复调用结果一致"的幂等要求。
4. 所有写页表项的路径都在写完之后调用 `tlb_invalidate()`，避免 CPU 继续使用旧映射。

### 功能模块二：进程创建及初始化

线程创建负责人为王泊凯，学号 2412224。模块通过 PCB 初始化、内核栈分配、
初始现场设置和 PID 登记，建立可供后续调度的内核线程。

#### 核心函数和数据

| 函数 | 实现内容 |
| --- | --- |
| `alloc_proc()` | 用 `kmalloc()` 分配并清零 PCB，设为 `PROC_UNINIT`、PID 为 -1，使用内核页表并初始化链表节点 |
| `proc_init()` | 初始化进程链表和哈希表，建立 PID 0 的 idleproc，复用 bootstack，设置 current 和调度请求，再创建、查找并命名 initproc |
| `kernel_thread()` | 清零临时 TrapFrame，把函数指针放入 s0、参数放入 s1，准备 status 和 epc 后调用 do_fork |
| `do_fork()` | 申请 PCB 和内核栈，设置父线程、页表和初始现场，分配 PID 并登记到链表、哈希表，唤醒后返回 PID |
| `copy_thread()` | 把 TrapFrame 放在新线程内核栈顶附近，设置子线程 a0、sp 以及 context.ra、context.sp |
| `copy_mm()` | 断言当前线程 mm 为空，完成本阶段内核线程的地址空间接口 |

`proc_struct` 保存管理信息，`context` 保存调度恢复所需的调用上下文，`tf` 指向线程
自己的 TrapFrame。普通线程拥有独立内核栈，并通过 `list_link` 参与调度。所有这些
内核线程的 `pgdir` 都指向 `boot_pgdir_pa`。

#### 首次执行现场与资源处理

`kernel_thread()` 在帧中设置 `SPP=1`、`SPIE=1`、`SIE=0`，使将来的 `sret` 返回
S 态并开启 S 级中断。修改的是新帧里的 status 值，当前构造函数的实际中断状态由
运行环境和临界区接口决定。`tf.epc` 指向 `kernel_thread_entry`，该入口把 s1 移到
a0，调用 s0 中保存的线程函数，函数返回后进入 `do_exit()`。

`copy_thread()` 把 `context.ra` 设为 `forkret`，把 `context.sp` 设为 TrapFrame
地址。线程第一次经 `switch_to()` 恢复后进入 forkret，由它传入当前线程的帧，
经过 `forkrets` 和 `__trapret` 恢复完整现场。

`do_fork()` 的内核栈申请失败时释放 PCB，地址空间准备失败时依次释放内核栈和
PCB。PID 分配、哈希表登记、链表登记和进程数量更新在本地中断保护内完成。

#### 行为规格与提示词记录

验收时，idleproc 应为 PID 0，使用启动栈且作为 current。initproc 应为 PID 1、
父线程为 idleproc、状态为 `PROC_RUNNABLE`，首次运行的 context 地址有效。
创建函数成功返回新 PID，失败返回负错误码，已申请资源按失败位置清理。

本模块按完整创建流程组织需求，以下为依据本次源码整理的规格摘要。

### 功能模块三：进程调度与上下文切换

负责人为成钧翔，学号 2411259。

#### 功能和实现范围

本模块将已经登记的可运行线程交给 CPU，覆盖空闲等待、选择运行对象、切换页表、
迁移寄存器现场四个环节。修改文件为 `kern/process/proc.c`、
`kern/schedule/sched.c`、`kern/process/switch.S`，保留 `LAB4 function3` 标记并填写学号。

| 函数 | 实现要点 | 可观察或核对的结果 |
| --- | --- | --- |
| `cpu_idle()` | 持续检查 current 的 need_resched，为真时调用 schedule | 初始化后能由 idle 进入调度 |
| `schedule()` | 清除调度请求，按链表顺序循环选择就绪线程，选择结果的 runs 加一 | 多个就绪线程能获得执行机会，缺少就绪线程时选择 idleproc |
| `proc_run()` | 在临界区中记住旧线程、更新 current、装入 Sv39 页表并调用 switch_to | 新线程身份、地址空间与执行现场一致 |
| `switch_to()` | 按 struct context 布局保存并恢复 ra、sp、s0–s11 | 新线程首次进入入口，旧线程恢复到此前调用位置 |

#### 线程选择与中断保护

`schedule()` 进入时使用 `local_intr_save()` 记录原状态并关闭本地 S 级中断。
当前为 idleproc 时从进程链表头之后开始查找，普通线程则从自身的下一个节点开始。
查找跳过链表哨兵，在完整一圈内寻找第一个 `PROC_RUNNABLE` 线程，找不到时使用
idleproc。若当前线程是唯一可运行线程，循环也能再次选择它。对睡眠和僵尸状态的
节点，代码跳过后继续搜索。

`schedule()` 和 `proc_run()` 分别保存中断状态。进入内层时中断已经关闭，其保存值
为假。恢复时只有对应层原本开启中断才重新开启，避免内层提前打开外层保护。

#### Sv39 页表和上下文切换

`proc_run()` 在目标与 current 相同时完成调用。目标不同时，保存旧线程指针并更新
current，按根页表的物理地址构造 `satp`，刷新 TLB 后调用底层切换函数。

```c
write_csr(satp, ((uintptr_t)SATP_MODE_SV39 << 60) |
               (proc->pgdir >> RISCV_PGSHIFT));
flush_tlb();
switch_to(&prev->context, &proc->context);
```

这里使用 64 位类型组合 Sv39 模式位和物理页号，参照框架 `enable_paging()` 的编码。
框架的 `lsatp(unsigned int)` 使用 Sv32 格式，本实现使用上面的 RV64 写法。

`switch_to()` 的 a0 指向旧 context，a1 指向新 context。按结构体顺序保存、恢复
ra、sp 和 s0–s11，共 14 个 8 字节槽，总计 112 字节，最后执行 `ret`。
恢复出的 ra 决定继续执行的位置，sp 决定随后使用的线程栈。函数调用约定让调用者
处理参数寄存器与临时寄存器的保存需求。

线程切出后，旧栈上的 `proc_run()` 调用暂停。旧线程以后再被选中，会恢复到
`switch_to()` 后，使用自己的栈中保存的 flag 恢复中断状态。新线程首次运行则先
经过 forkret 和 Trap 返回链，按预先构造的帧恢复权限与中断使能状态。

### 扩展练习与原理分析

#### 本地中断保存与恢复

`local_intr_save(flag)` 检查 `sstatus.SIE`。原来开启时先关闭并返回真，原来关闭时
返回假。配对恢复时只有 flag 为真才调用 `intr_enable()`。嵌套调用各自保存 flag，
按从内到外的顺序恢复。宏中的 `do { ... } while (0)` 让宏体作为一条语句使用。
这一机制保护单 hart 上可能与中断路径共享的状态，跨 hart 的访问还需锁或原子同步。

#### 多级页表和 get_pte 的结构

| 模式 | 页表层数 | 每层索引位数 | 基本页大小 |
| --- | --- | --- | --- |
| Sv32 | 2 | 10 | 4 KiB |
| Sv39 | 3 | 9 | 4 KiB |
| Sv48 | 4 | 9 | 4 KiB |

当前 `get_pte()` 先查最高层，再查中间层，最后返回末级项地址。两段相近代码分别
处理缺失的下一层页表，需要分配物理页、设引用计数、清零并登记表项，所以步骤相似。
Sv48 会再增加一层类似查找，Sv32 则减少一层。

把查找和创建合在 `get_pte(pgdir, la, create)` 中，让调用者可以复用同一套遍历，
但调用时要清楚 create 是否允许分配内存。拆成查询和创建接口可以明确副作用，
同时需要避免重复维护遍历逻辑。此次实现沿用现有接口。中间层创建到一半发生内存
不足时的回收属于需要进一步核对的边界，当前评分的正常分配用例未覆盖这类失败注入。

## 六、实验总结与收获

### 与 OS 课程知识的对应

| 知识点 | 本实验中的体现及关系 |
| --- | --- |
| 地址映射和引用计数 | page_insert、page_remove 维护共享物理页的映射数量，写表后执行 TLB 同步 |
| 进程控制块和线程资源 | proc_struct 记录状态、PID、父线程、栈和上下文，各内核线程共享内核地址空间 |
| 调度与上下文切换 | schedule 决定谁运行，proc_run 和 switch_to 完成身份、页表及寄存器迁移 |
| 函数调用与 Trap 恢复 | switch_to 保存调用约定要求的 context，首次运行借助完整 TrapFrame 和 sret 进入线程入口 |
| 临界区与中断 | 保存并关闭本地中断保护切换过程，各层恢复自己进入时的使能状态 |

本次调度测试通过线程主动调用 `schedule()` 验证多次切换。完整时间片抢占还需要
时钟处理、调度请求与安全调度点配合。用户态程序隔离、系统调用、按需缺页、页面
置换、进程等待与资源回收，以及多核同步等内容，需要在后续实验中继续实现。

### AI 协作开发的经验

提示词按完整调用链给出任务，使生成代码能同时考虑线程创建、首次恢复和后续
再次调度之间的接口。结构体布局、页表地址含义和中断状态需要写成可核对的约束，
才能逐项检查生成结果。

此次先核对线程创建、页表切换和寄存器恢复之间的接口，再用普通 QEMU 和原有
评分脚本验证。初次编译中的类型诊断促使我们记录工具链版本和兼容参数。运行中
的退出 panic 则通过追踪线程入口到 do_exit 的调用关系解释。编译、单次输出和
多个线程恢复执行分别提供不同范围的证据，报告按实际执行记录说明结果。
